# Contributing

Documentation is the product in this repository. Keep changes direct,
operational, and easy to verify.

## Workflow

1. Create or update a CaaS entry under `src/content/docs/services/`.
2. Run `just format`.
3. Run `just check`.
4. Open a pull request against `main`.

CI rejects formatting drift, invalid frontmatter, missing required sections,
Markdown lint failures, Astro type errors, broken builds, and invalid Helm
templates.

The `deploy` branch is generated by GitHub Actions. Never edit it manually.

## Style

- Address the service consumer directly.
- Prefer working examples over general explanation.
- Keep commands copyable and explicit.
- Explain operational limits and ownership.
- Never commit real credentials or internal secret values.
